## 環境（Windows・Google Drive・リモートデスクトップ）

| 症状 | 原因 | 対処 |
|---|---|---|
| Python の正規表現がおかしい、`SyntaxWarning: invalid escape sequence` | Bash のヒアドキュメントで `\\` が `\` に化ける | 正規表現を含む Python は **Write ツールでファイルに書く**。Bash のヒアドキュメントで書き換えない |
| 日本語の表示が化ける／`UnicodeEncodeError: cp932` | コンソールが cp932 | スクリプト先頭で `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8")`。印字に「–」「—」を使うなら特に |
| 【】入りのファイル名が見つからない | ダウンロードしたファイル名が NFD | `unicodedata.normalize("NFC", name)` で比べる |
| .ps1 が `Unexpected token ')'` で動かない | Windows PowerShell 5.1 は BOM なし UTF-8 を ANSI として読む | .ps1 は ASCII だけで書く（日本語のコメントを入れない） |
| `PermissionError` で .docx を保存できない | ユーザーが Word で開いている（同じフォルダに `~$…docx`） | 閉じてもらう。変更がない書類なら生成対象から外す。ロックファイルは消さない |
| `git status` で、作った覚えのない提出物が変更扱いになっている | PI が Word で手直しして保存した（作成者欄が本人、更新時刻が作業外） | **生成スクリプトで上書きしない**。`safe_save` / `guarded_save` が止める。手直しを反映してから `--force`、または Word の版を正本にして最小限だけ直す |
| Word の PDF 書き出しが無言で止まる | 自動操作の Word（`/Automation -Embedding`）が応答しなくなる。2026-09-17 は、同じ書類で成功と失敗が入れ替わった。原因は特定できていない。疑いは、前回止まった Word の残骸、リモートデスクトップ経由の既定プリンタ（TS001）、ユーザーが Acrobat を開いているときの PDFMaker アドイン（止まり始めた時刻と Acrobat の起動が近かった）、EndNote のアドイン | `docx_to_pdf.ps1` は時間切れで**自分が起動した自動操作の Word だけ**を止める。ユーザーが開いた Word（`/n "…"`）や Acrobat は止めない。既定プリンタの変更もユーザーの設定なので勝手にしない。PDF で確かめられないときは、`dump_template.py` と `audit_docs.py` で構造を確かめ、見た目の確認はユーザーに頼むか後で回す |
| 止まった Word が翌日まで残っていた | バックグラウンドのシェルを止めても COM の Word は残る | `Get-CimInstance Win32_Process -Filter "Name='WINWORD.EXE'"` の CommandLine で `/Automation -Embedding` を見分けて止める |
| Remove-Item がシステムパスで拒否される | サンドボックスの制限 | 作業フォルダの中だけで消す |
| `git add -A` が固まる | リポジトリが Google Drive 上 | ファイルを名指しで add する。フォルダ単位の add は小さいフォルダだけ |
| `git commit` で Author identity unknown | このリポジトリに user.name がない | 既存コミットの作者（`git log -1 --format='%an <%ae>'`）を `git -c user.name=… -c user.email=… commit` で渡す。設定は書き換えない |
| PowerShell の `Stop-Job` が何分も返らない | ジョブの中の COM 呼び出しが止まっている | 先に Word を止め、ジョブの子プロセス（`-s -NoLogo`）を止めてから `Remove-Job -Force` |

## 書類の中身

| 症状 | 対処 |
|---|---|
| 抄録では「結果に使ったものだけ方法に書く」と直されたのに、計画書で同じことをした | 計画書は**取得する情報をすべて**書く（委員会は何を集めるかを見る）。抄録と計画書でルールが違う |
| 研究対象者を研究者欄に書いた | 研究に参加して計測されるだけの人は研究者ではない |
| 説明文書で「入力は不要」と書いた | 業務ログなど手入力があるなら手入力と書き、1日の所要時間を書く |
| 書類に出ない人がデータを扱う案にした | 実態と書類を一致させる。データを扱う人は研究分担者・事務局として載せる |
| 名前や番号を推測で埋めた | 【氏名】【　　】のまま残し、手引きの「未記入の欄」に載せてユーザーに聞く |
| 機械の点検で要修正0件だったので「指針に合っている」と答えた | 形の点検にすぎない。中身（実態・引用・書類間）は SKILL.md の「点検の手順」で見る。2026-09-17 は要修正0件の書類に、課題名の行の欠落、サーバーの記載と実態の食い違い、計画書にない取得項目などがあった |
| 「サーバーには研究用IDだけ」のようにシステムの記載を実物で確かめずに書いた | データベースの表・アプリの入力欄・外部サービスを見て確かめる（実際には表示名やメールアドレス、位置に関わる値が入っていたことがある） |
| 引用した文献が主張（「20〜30人で足りる」）を支えていなかった | 抄録で確かめる。数の根拠はシミュレーションで示す |
| 委員会様式02（共同研究機関の研究責任者の宣言）を代わりに☑した | 本人に確認してもらう（研修の受講など、本人しか分からない） |
